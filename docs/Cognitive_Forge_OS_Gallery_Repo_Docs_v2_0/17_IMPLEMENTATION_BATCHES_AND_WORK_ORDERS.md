# D17 IMPLEMENTATION_BATCHES_AND_WORK_ORDERS

버전 2.0 · 2026-11-01 · 구현 지시 명세

## 목적과 범위
개발 순서, 선행 조건, 대상 모듈·파일, 필요한 마이그레이션, 구현 작업, 검증 명령, 완료 증거와 복구 방법을 티켓으로 분해한다. 티켓별로 관련 요구사항과 명세를 연결한다.

현재 레포의 typecheck·test·build·fixtures:validate 등의 스크립트를 확인해 사용한다. 필요한 검사만 단계에 맞춰 지정하고, 실행하지 않은 명령을 성공으로 기록하지 않는다.

## 구현 결정
T01 계약·상태, T02 실제 실행·저장, T03 제작기, T04 평가·릴리스, T05 검수·산출물, T06 지속 실행, T07 외부 인터페이스, T08 전환·출시 순서다. 각 티켓은 대상 경로·선행 티켓·구현 내용·인수 기준·복구 방법을 포함한다. 제품 담당자가 화면의 완료 조건을, 백엔드 담당자가 계약과 저장을, QA가 실패 조건과 증거를 확인한다. 타 프로젝트 전체 통합은 T08의 필수 조건이 아니다.

## 계약 및 검증 연결
공통 객체는 06_CANONICAL_OBJECTS_AND_STATE_CONTRACTS.md, 인터페이스는 13_PUBLIC_API_EVENTS_AND_INTEROPERABILITY.md를 따른다. schemas/, examples/, tickets/, tests/의 동일 식별자를 사용한다. 상태 변경 시 revision을 검사하고 결과 버전을 보존한다.

## 완료 증거
담당자는 변경 파일 목록, 검사 결과 원문, 실패·미실행 항목과 복구 방법을 남긴다. 명세 작성 완료는 소프트웨어 구현 완료를 뜻하지 않는다.

## 갤러리 v2 개정 계약
G0~G5 문서 배치를 완료하되 구현 티켓 GX01~GX06은 NOT_IMPLEMENTED다. 기존 T01~T08과 선행 관계를 연결한다.
