# D10 EVALUATION_AND_RELEASE_QUALIFICATION

버전 2.0 · 2026-11-01 · 구현 지시 명세

## 목적과 범위
형식 검사, 결정론적 업무 검사, 모델 평가, 사람 평가를 구분한다. 긍정·실패·경계 사례, 반복 실행, 기준 버전 비교, 중대 실패 조건, 미측정 상태, 버전 승격과 회귀 판정 방법을 정의한다.

모델 평가 점수만으로 납품 가능 상태를 부여하지 않는다. 평가 데이터와 개발 사례를 구분하고, 일부 미사용 사례를 별도 검증에 활용한다. 제작 초안·시험 완료·현장 검증을 별도 성숙도로 표시한다.

## 구현 결정
형식 검사→업무 규칙 검사→모델 평가→필요 시 사람 검수 순서로 판정한다. 사실 날조, 교차 고객 노출, 무권한 외부 실행은 중대 실패다. 대표·실패·경계 입력을 마련하고 동일 조건 반복 실행을 비교한다. 모델 평가만으로 중대 실패를 무효화하지 않는다. 릴리스는 필수 검사 통과, 미해결 중대 실패 없음, 제작자 발행 확인을 요구한다. 현장 검증 표시는 실제 고객 시험 증거가 있을 때만 허용한다. 이 패키지의 예시 검증은 실제 모델 품질 검증이 아니다.

## 계약 및 검증 연결
공통 객체는 06_CANONICAL_OBJECTS_AND_STATE_CONTRACTS.md, 인터페이스는 13_PUBLIC_API_EVENTS_AND_INTEROPERABILITY.md를 따른다. schemas/, examples/, tickets/, tests/의 동일 식별자를 사용한다. 상태 변경 시 revision을 검사하고 결과 버전을 보존한다.

## 완료 증거
담당자는 변경 파일 목록, 검사 결과 원문, 실패·미실행 항목과 복구 방법을 남긴다. 명세 작성 완료는 소프트웨어 구현 완료를 뜻하지 않는다.

## 갤러리 v2 개정 계약
제작자 정보 확인·에이전트 평가·검수 제공을 세 축으로 표시한다. 파생 팩은 재평가하며 원본 배지를 자동 상속하지 않는다.
