# D09 RUNTIME_ORCHESTRATION_AND_TOOL_EXECUTION

버전 2.0 · 2026-11-01 · 구현 지시 명세

## 목적과 범위
실제 모델 어댑터, 단일 실행, 단계 연결, 조건 분기, 추가 질문, 검수 대기, 재시도, 취소, 예산, 시간 초과, 작업 재개를 정의한다. 장시간 작업은 요청 처리와 실행 작업을 분리하고 상태를 영속 저장한다.

도구는 허용된 입력·출력·권한과 부수 효과를 선언한다. 외부 상태 변경에는 중복 실행 방지, 결과 확인, 불확실한 성공 상태 처리 기준이 필요하다. 체크포인트만으로 정확히 한 번 실행이 보장된다고 표현하지 않는다.

## 구현 결정
RunService는 인증→권한→릴리스 스냅샷→예산 예약→큐 적재를 수행한다. Worker는 작업 lease를 획득하고 노드 전후 체크포인트를 저장한다. 사람 대기는 worker를 점유하지 않는다. 재개 시 원래 팩·자료·평가 버전을 사용한다. 읽기와 생성 실패는 기본 최대 2회 재시도하며 총 예산·시간 한도가 우선한다. 외부 상태 변경이 시간 초과되면 성공 여부를 조회하기 전 재전송하지 않는다. 취소는 이미 발생한 외부 효과를 자동으로 되돌렸다는 뜻이 아니다. JSON 파싱 실패와 제공자 통신 실패를 구분한다.

## 계약 및 검증 연결
공통 객체는 06_CANONICAL_OBJECTS_AND_STATE_CONTRACTS.md, 인터페이스는 13_PUBLIC_API_EVENTS_AND_INTEROPERABILITY.md를 따른다. schemas/, examples/, tickets/, tests/의 동일 식별자를 사용한다. 상태 변경 시 revision을 검사하고 결과 버전을 보존한다.

## 완료 증거
담당자는 변경 파일 목록, 검사 결과 원문, 실패·미실행 항목과 복구 방법을 남긴다. 명세 작성 완료는 소프트웨어 구현 완료를 뜻하지 않는다.

## 갤러리 v2 개정 계약
비교 작업도 각각 독립 run_id와 고정 릴리스를 가진다. 카탈로그가 preview_only이면 RunService 앞단에서 실행을 거부한다. capability 누락을 프롬프트 지시로 대체하지 않는다.
