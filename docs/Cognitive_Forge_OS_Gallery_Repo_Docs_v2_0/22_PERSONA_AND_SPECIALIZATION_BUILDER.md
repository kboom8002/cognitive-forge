# D22 페르소나·특화 제작기

## 7단계 작성
기본 에이전트 선택→고객과 목적→허용 자료와 사례→판단 기준→출력·검수→비교 시험→내 이름으로 발행 순서다. 이름·사진·소개는 실행 지시와 분리한다. 페르소나의 신중함은 정보 부족 시 질문하는 규칙으로, 간결함은 조건을 보존하는 출력 규격으로 연결한다.

## 컴파일 계약
원문 작성 내용을 보존하고 A 역할·독자, S 범위, T 납품물, K 참조·사례·현재 입력, W 검사·중대 실패, F 단계·중단, L 표현, O 구조로 정규화한다. AI가 제안한 새 규칙은 제작자 확인 전 draft다. source_map에 각 실행 규칙의 원문 출처를 남긴다. 기본 팩과 차이 비교는 고객군·사례·판단·출력·도구·검수 범위를 보여준다.

## 복제·시험
fork는 parent_release_id를 고정하고 새 소유자의 비공개 draft를 만든다. 원본 고객 자료·자격증명·비공개 평가 자료는 복사하지 않는다. 원본이 업그레이드되어도 자동 덮어쓰지 않고 비교 후 반영한다. 이름만 변경한 버전은 개인용으로 허용하되 독자적 전문성 검증 표시를 주지 않는다.

## 발행
필수 입력·출력 스키마, 동작 검사, 사용 권한, 공개 소개, 실행 capability를 확인한다. 생성 모델이 발행을 승인하지 않는다. 제작자의 발행 의사와 서비스의 기술적 gate를 모두 기록한다. 검증되지 않은 서비스도 예시로 공개할 수 있지만 실행 가능 상태와 구별한다.
