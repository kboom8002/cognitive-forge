# D15 MIGRATION_COMPATIBILITY_AND_ROLLOUT

버전 2.0 · 2026-11-01 · 구현 지시 명세

## 목적과 범위
기존 CasePack·Graph·앱 주소·DB·문서의 유지·변환·대체 범위를 파일 또는 객체 단위로 정리한다. 레거시 읽기, 새 버전 작성, 사전 변환 검사, 백업, 점진 전환, 이전 버전 복구 절차를 정의한다.

진행 중 실행은 시작 당시 정의·모델·자료·평가 정책 버전을 고정한다. 활성 버전을 바꿔도 진행 중 실행의 의미가 바뀌지 않아야 한다. 파괴적인 변환을 기본 경로로 두지 않는다.

## 구현 결정
기존 core 01 PRD와 02 SDD는 새 제품 경계로 개정하고 03 객체 표준은 D06과 통합한다. implementation 04~08은 각각 D05·D06/D07·D12·D13·D04/D09와 대조하여 개정한다. 기존 팩은 읽기 호환 어댑터로 지원하고 새 버전은 별도 저장한다. DB는 신규 열·테이블 추가→백필→이중 읽기 검증→기능 플래그 전환 순서로 진행한다. 이전 릴리스 포인터로 복구하되 이미 실행된 외부 효과는 별도 보상 절차를 따른다. 진행 중 run을 최신 버전으로 자동 교체하지 않는다.

## 계약 및 검증 연결
공통 객체는 06_CANONICAL_OBJECTS_AND_STATE_CONTRACTS.md, 인터페이스는 13_PUBLIC_API_EVENTS_AND_INTEROPERABILITY.md를 따른다. schemas/, examples/, tickets/, tests/의 동일 식별자를 사용한다. 상태 변경 시 revision을 검사하고 결과 버전을 보존한다.

## 완료 증거
담당자는 변경 파일 목록, 검사 결과 원문, 실패·미실행 항목과 복구 방법을 남긴다. 명세 작성 완료는 소프트웨어 구현 완료를 뜻하지 않는다.

## 갤러리 v2 개정 계약
기존 /a/[slug] 유지, 갤러리 노출은 opt-in이다. 신규 테이블 추가→비공개 seed→미검증 표시 검증→12종 개별 승격 순서다. 원본 릴리스와 고객 실행은 이관 시 변경하지 않는다.
