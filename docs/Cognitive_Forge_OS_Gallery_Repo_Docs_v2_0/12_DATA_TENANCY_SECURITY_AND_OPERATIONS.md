# D12 DATA_TENANCY_SECURITY_AND_OPERATIONS

버전 2.0 · 2026-11-01 · 구현 지시 명세

## 목적과 범위
DB 변경, 작업공간 격리, RLS, 역할, 자격증명 보관, 공개 앱 이용 제한, 사용량 한도, 보존·삭제, 로그의 민감정보 처리를 정의한다. 입력 문서 속 지시가 상위 정책이나 도구 권한을 바꾸지 못하도록 실행 계층에서도 제어한다.

zeroRetention의 의미는 입력·출력·첨부·추적·이벤트·백업 등 저장 위치별로 정의한다. 최소 운영 계측과 고객 콘텐츠 보존 정책을 구분한다. 장애 관찰, 비용 제한, 복구와 운영자가 확인할 화면도 포함한다.

## 구현 결정
모든 고객 자료 테이블에 workspace_id와 해당 작업공간을 포함한 참조 무결성을 적용한다. 사용자 입력 workspace_id를 신뢰하지 않고 인증 문맥으로 결정한다. 서비스 역할 키는 서버에만 둔다. 업로드·run 입력·출력·trace·webhook payload·백업별 보존 기간과 삭제 가능 시점을 설정표로 관리한다. 내용 미보존 모드에서도 최소 비용 계측을 별도 분리하며 고객 콘텐츠를 기록하지 않는다. 운영 로그는 비밀값을 제거한다. job lease 만료와 미전달 이벤트는 운영 화면에서 재처리한다.

## 계약 및 검증 연결
공통 객체는 06_CANONICAL_OBJECTS_AND_STATE_CONTRACTS.md, 인터페이스는 13_PUBLIC_API_EVENTS_AND_INTEROPERABILITY.md를 따른다. schemas/, examples/, tickets/, tests/의 동일 식별자를 사용한다. 상태 변경 시 revision을 검사하고 결과 버전을 보존한다.

## 완료 증거
담당자는 변경 파일 목록, 검사 결과 원문, 실패·미실행 항목과 복구 방법을 남긴다. 명세 작성 완료는 소프트웨어 구현 완료를 뜻하지 않는다.

## 갤러리 v2 개정 계약
공개 프로필은 내부 계정 자료와 분리한다. fork·비교·매칭 요청에 작업공간 권한과 호출 한도를 적용하고 외부 콜백과 원문 자료를 공개 이벤트에 노출하지 않는다.
